# Implementation notes

Decisions taken while implementing `docs/H2Py-DESIGN.md` (v1.6) that the design leaves open, or that deviate from its text.
Each entry names the section it touches and why.
The design document itself is kept as written; these notes are the amendments.

## Build and distribution (5.10, R1)

1. **Weak CPython references on macOS.**
   GHC loads `libHSh2py` into its own process, with no interpreter, to run the Template Haskell splices of any module that uses `pyclass`, `pymethods` or `pymodule`, and dyld on current macOS binds every symbol of a library at load time; so any CPython reference in the library, function or data, makes that load fail.
   Cabal passes neither `ld-options` nor `ghc-shared-options` to a library's dylib link, which rules out a linker flag.
   The library therefore references the interpreter only through weak imports: every Haskell `foreign import` goes through a one-line wrapper in `h2py/cbits/api.c`, every C translation unit of the shim includes the generated `include/h2py/weakapi.h` (`#pragma weak` per symbol, regenerated by `scripts/gen-weakapi.sh` from the undefined symbols of the built dylib and verified by `--check`), and no CPython data symbol is referenced anywhere: `PyExc_*`, `Py_None`, `Py_True`, `Py_NotImplemented` and the built-in type objects are fetched through `builtins` at first use and cached in `h2py.c`.
   Linux needs the data-symbol half of this, since a lazy `dlopen` tolerates an undefined function but not undefined data; the same source builds there unchanged.
   The design owner accepted the scheme as the design (it also keeps the library loadable in `cabal repl` and HLS without an interpreter), with two conditions that are met: the no-data-symbol rule is a stated invariant, and the check is wired into the build as the `h2py-weakcheck` test suite (a source lint plus, on macOS, an `nm -m` pass over the built dylib).
   The recorded fallback, should the weak scheme prove fragile, is a splice package that does not depend on `h2py` and emits names with `mkNameG`.
2. **`-undefined dynamic_lookup`** is what GHC already passes when it links a dylib on macOS; the `ld-options` in the cabal files matter only for the foreign library's final link.
3. **RTS options.**
   The example module passes `-N` through `H2PY_RTS_OPTS` in its C file, as 5.9 recommends for the demo; the library itself adds only `--install-signal-handlers=no`, and the `H2PY_RTS_OPTS` environment variable is appended at initialisation.
   `keep_cafs` is on, because the RTS lives in a library whose code is entered through adjustors long after initialisation.
4. **Extension file name.**
   Cabal names the artifact `libh2py_examples.dylib`; `scripts/install-module.sh` copies it to `build/h2py_examples.abi3.so`, which CPython imports.
5. **linear-base 0.7.**
   `cabal.project` constrains linear-base to the 0.7 series, matching pure-borrow's freeze and CI matrix, on the design owner's decision; nothing needed 0.8.

## The `Py` world and the delimiters (5.1)

6. **Fresh scopes.**
   Lifetimes are erased, so a rank-2 body is instantiated at `'Al 0` behind `withFreshScope`; the rank-2 binder is what keeps the body from assuming anything about the scope, exactly as `newLifetime'` does upstream.
7. **Finalisation on the restore path.**
   When `detach`'s restore finds the interpreter finalising, `DetachRestoreRefused` is thrown; the trampoline's exceptional path then finds the thread unattached, releases the arena's Haskell state without touching CPython (the +1s leak), and parks the thread for good, which is CPython's documented behaviour for a daemon thread at exit.
8. **`parPy` and branch exceptions.**
   `parBO` at the pinned commit does not propagate a branch's exception (the structured version of 4.4 is a later upstream change), so a Haskell exception inside a `parPy` branch can hang the call; the shipped kernels validate their inputs first and answer `Left`.

## References, errors, conversions (5.2, 5.5, 5.6)

9. **Constants of the interpreter** (`None`, `True`, `False`, `NotImplemented`) are registered in the arena like any other reference when handed out as `Bound`, with an incref, so that the sweep's uniform decref stays correct.
10. **Lazy errors** hold the exception class as a raw pointer: static for the built-ins (read through a pure foreign import of `h2py_exception_type`, which touches no interpreter state), and for classes made by `newException` an `IORef` cell filled at module init and read through a `NOINLINE` `unsafePerformIO`, so that `pyErr` stays pure as 5.5 asks.
    The cell is write-once: a second fill and a read before the fill are an `error` naming the class, never a `NULL` that reaches CPython; nothing can force a `pyErr` value before init, since Haskell code runs only inside calls.
11. **`fromPy` for containers** iterates in an IO loop inside the trusted library and releases each item's reference as soon as it is converted, instead of wrapping each iteration in `attach'_`: those references never become a `Bound` visible to user code, so they need no arena slot and no constraint; `attach'`/`attach'_` are the loop tools for user code, which cannot release early.
   Confirmed by the design owner and recorded in 5.6.
12. **`ToPy` for `Set` and `Map`** is not provided, because linear-base has no `Consumable` instance for them and `ToPy` requires one; `FromPy` for both exists.
13. **`Integer` beyond 64 bits** goes through `PyNumber_ToBase(…, 16)` and a decimal string in the other direction; the limited API has no direct big-integer accessor at the 3.12 floor.
14. **`PyObject_Length`** is a macro alias of `PyObject_Size` in the headers; the weak list carries the real symbol.

## Registration (5.4, 5.11, 5.12)

15. **The `detached` registration** is a marker newtype `Detached f` wrapped around the whole function value, selected by `& detached`, with `PyCallable` and `PyMethod` instances that push it through the arrows to the body; a `BO π` or `BIO π` body then runs under `detach`, and marking a `Py π π` body is a type error, since a `Py` body cannot be detached (the design owner's condition).
16. **Option combinators are multiplicity-polymorphic** in the registration (`param 0 "x" :: s %m -> s`) and `H2Py` re-exports no `&`, so that `fn "add" 'add & param 0 "x"` chains under `Data.Function`'s and `Prelude.Linear`'s `&` alike; a registration table is plain data.
17. **`pymethods` is required** for every class listed in a `pymodule`, with an empty list for a class without methods, because `pyclass` cannot know whether a `pymethods` follows.
18. **Class names are module-qualified** in the type spec (`h2py_examples.Counter`), which is what gives the class its `__module__`.
19. **Module docstrings** come from the Haskell description (`msDoc`), set as `__doc__` at init; the C `PyModuleDef` carries none.
20. **The `foreign export`** that `pymodule` generates is typed `Ptr PyObject -> IO Int32`, because a `CInt` result would need the constructor in scope in the user's module.
21. **Class type cells** are top-level `NOINLINE` `IORef`s generated per class; a class used before its module is initialised answers `RuntimeError`.

## Buffers (5.7)

22. **View scopes.**
    `requestBufferMut` is typed `Bound π PyAny %1 -> Py π γ (PyResult (BufferMut π e))`, the request scope being the view scope, and `requestBufferShare` answers a view at the requesting scope, because the shim records a view in the innermost arena and a view at an outer scope could outlive the arena that releases it; `withBufferMut`, `withBufferShare`, `releaseBuffer` and `newArray` keep the design's signatures (see `Note [Buffer views are scoped by the requesting arena]`).
23. **NumPy's own errors** for a read-only or non-contiguous array (a `ValueError` from `PyObject_GetBuffer`) are rewritten into `BufferError`, which is what the design promises.
24. **`Bool` buffers.**
    `Storable Bool` is four bytes wide, so NumPy's one-byte `bool_` arrays match the `CBool` instance, not `Bool`.
25. **The registry flag** is recorded on the view at request time: a shared view of a writable exporter has `readonly == 0`, so the flag cannot be recovered from the `Py_buffer` (a bug the tests found).

## Concurrency (5.1, 5.8)

26. **`parPy` guards its branches**: each runs under `try` after its own attachment has been released, and the parent rethrows the first exception once both have completed, so a Haskell exception in a branch reaches the trampoline as a Python exception instead of hanging; an asynchronous exception delivered to the waiting parent still leaves the branches running to completion, which only the structured upstream `parBO` removes.
27. **`KeyboardInterrupt` and attached loops.**
    A Python timer thread cannot deliver `interrupt_main` while a call holds the interpreter, so `checkSignals` inside an attached loop only ever sees a real signal (the tests send `SIGINT` from a subprocess); the design's shape, detach for the long stretch and check after, is `sleep_then_check` in the examples.

## Packaging (5.10, 5.11)

28. **Wheels** are built by a hatchling hook that runs `cabal build` from the repository checkout, and repaired with `delocate` on macOS: 36 Haskell runtime dylibs are bundled, 12.8 MB compressed and 62 MB unpacked; the platform tag follows the minimum OS version the libraries were built for, so a portable wheel needs `MACOSX_DEPLOYMENT_TARGET` set when the store and the tree are built.
    `libgmp` is statically linked into GHC's `ghc-bignum` on macOS, so no LGPL dylib is bundled there.
    Superseded by 54 to 58: the environment variable does not reach a store that already exists, and the macOS wheels convey GMP all the same, inside `libHSghc-bignum`.
29. **Stubs** are written by `scripts/h2py-stubs.py` from `__h2py_stub__`, and `mypy --strict` passes on the example's root stub; a class registered with an ABC renders the ABC as a base without type arguments, which `mypy --strict` rejects for `Sequence`.

## Measured (Phase 1 gate, R3, and Phase 4)

On this machine (Apple silicon, CPython 3.13.0, GHC 9.12.4, `-O2`, `-N`), per call, median of 50k calls:

| call | ns |
|------|----|
| `add(1, 2)` | 740 |
| `c.incr(1)` | 610 |
| `c.get()` | 540 |
| `c.label()` | 690 |
| pure Python `add` | 33 |

The path measured is the real one: adjustor entry on a bound thread, `mask`, pool drain, arena push, argument binding and conversion, the dereference and its compare-and-swap, result incref, sweep and pop.

`nparallel.sort_in_place` (`qsortDC` over a `float64` buffer, detached, `-N` on 10 logical cores) against `numpy.sort`, best of 5:

| n | `numpy.sort` | `sort_in_place` |
|---|---|---|
| 1e5 | 2.1 ms | 2.2 ms |
| 1e6 | 26.4 ms | 22.7 ms |
| 1e7 | 327 ms | 227 ms |

`nparallel.sum` reads each half of the shared view with an indexed loop, since the unrestricted vector API has no fold, and is about 2.2 times slower than `numpy.sum` at 1e7; `nparallel.fft` (pure-borrow's `fftDC`, two conjugation passes around it to match NumPy's sign convention) is far slower than pocketfft and carries the twiddle recurrence's drift, which the README's Numbers section quantifies with a core-count sweep from `scripts/bench-nparallel.py`.

## The adversarial review round (2026-09-23)

Four reviewers with one lens each (linear ownership, type-level soundness, runtime/FFI/concurrency, ergonomics and the phase gates) were told to refute the integrated implementation; every substantial finding was then handed to two independent refuters, and none was refuted.
What each confirmed finding changed:

30. **Shared buffer views cannot be released early from safe code.**
    `BufferShare` is unrestricted, so `releaseBufferShare` on it typechecked twice; the shim's release is now idempotent, the view struct lives until the sweep of the arena that recorded it, and the function is no longer exported from `H2Py.Buffer`.
31. **Trusted instances are sealed** (`Note [Sealed classes]` in `H2Py.Object.Internal`): `PyClass`, `PyFrozenClass`, `PyTypeOf`, `PyExtends` and `PyExceptionClass` carry a witness method whose constructor only the `.Unsafe` and `.Internal` modules export; the splices produce it, every trusting operation forces it, and a hand-written instance in safe code cannot retag a reference, alias another class's cell or lie about a type object.
32. **No `NULL` type object reaches CPython**: a generated `pyTypeOf` throws `ClassNotRegistered` (a `RuntimeError` in Python) before its module is initialised.
33. **C stack headroom** is checked at every trampoline entry (`h2py_call_begin`) and a call with less than 256 KB left raises `RecursionError`, because a Python recursion through H2Py costs far more C stack per level than CPython's own accounting assumes.
34. **The constant caches are warmed at module exec**, so a lazy `PyErr` forced on a detached thread never imports anything.
35. **The forked-child guard is on the trampoline**, not only on `attach`: every call in the child of `os.fork()` raises `RuntimeError` naming the `spawn` start method.
36. **Subtype allocation is paired with its class**: the type a `tp_new` records is taken only by the first allocation of that class in the constructor, searched outwards through nested scopes, so a helper object built inside a constructor gets its own type.
37. **Linear values are consumed on every `Left` path** of `newObject`, `newObjectWith` and the list, vector and tuple `ToPy` instances.
38. **`parPy` and `parBIO` guard their branches** (see 26); a user kernel is written `detach (parBIO …)` for now.
    `parBIO` is interim by decision of the design owner: it goes when the structured upstream `parBO` of Phase 0.5 lands, so that the API never carries two parallel combinators for good.
39. **`PyHandle` is `Dupable` and `Movable`**, as an unrestricted handle should be; `call0`, `callMethod0` and `emptyTuple` give the zero-argument shapes a type.
40. **Deallocators report a Haskell exception** through the unraisable hook with the converted error raised, saving and restoring the caller's pending exception.
41. **`copyPayload`'s transient claim** is taken and released under `mask`.
42. **Arenas that lost the interpreter** are abandoned without touching CPython on the `attach` and `attach'` exit paths too.
43. **Stubs import every module a dotted hint refers to**, and the built-in container tags render with type arguments.
44. **Cycle collection** stays a documented non-goal of 0.1 (design section 1): a `PyHandle` stored in a payload is invisible to CPython's cycle collector, so a cycle through a Haskell payload leaks.
45. **Gate coverage** (every operation's refcount deltas, callback re-entrancy, asynchronous poisoning, `attach'` hold release, receiver-form `BIO` bodies, the fork and recursion guards, `fft` and a stencil in `nparallel`, the `qsortDC` inspection, the counter's golden stub) was added in a second round of work packages after the fixes above.
46. **Slot bodies in both forms.**
    `Compare`, `GetItem`, `SetItem`, `DelItem`, `Next`, `Exit` and the in-place number operations accept a body returning `r` or `PyResult r` through a small `SlotResult` class, as methods do through `ToResult`; `Iter`, `NextObject`, `Enter` and the binary and unary number operations keep the `PyResult` form, because their result is a reference at the call's scope, which an existential chosen outside the scope-polymorphic body cannot name.
47. **Registrations are looked up module-qualified first** by `pymodule`, so two classes with one base name in different modules (the tutorial's `Counter` next to the example's) resolve to their own registration.
48. **`PyHandle` is `Copyable`** as well, so a payload holding a `Ref (Maybe (PyHandle t))` reads it back with `copyRef`; the tutorial has the section.
49. **Stubs under `mypy --strict`.**
    The example's stub package (root plus one file per submodule) is committed under `h2py-examples/stubs/`, regenerated by `scripts/h2py-stubs.py --output`, checked by `--check` in `scripts/test-all.sh` and CI, and passes `mypy --strict`; generic ABC bases render with `Any` type arguments, `__contains__` takes `object`, a class registered but deliberately absent from every module is hinted `Any` by its example.
    The example's `Stack` registers `collections.abc.Sized` rather than `Sequence`, since a stack without slice support is not a typed sequence.
50. **The `qsortDC` inspection** at `Storable Double` finds the workload specialised but the scheduler's `Traversable` and `RandomGen` dictionaries retained, because pure-borrow's `divideAndConquer'` has no `INLINABLE` pragma; the wanted property is recorded with `expectFailBecause` in the `h2py-inspection` suite, and the fix is upstream.
51. **Gate tests added**: every operation's refcount deltas on success, `Left` and exception paths; callback re-entrancy answering `busy`; two handles to one object; asynchronous poisoning through `timeout` and `throwTo`; a hold released at the end of `attach'`; receiver-form `BIO` and detached `BO` bodies releasing the interpreter; a `parBIO` branch error surfacing as `RuntimeError`; the fork and recursion guards in subprocesses; an unregistered class answering `RuntimeError`; a hand-written unsealed instance failing at first use; a subclass constructor building helpers of their own type.

## Redistributable wheels (2026-09-23)

The first CI run, on the initial commit, failed on both Ubuntu jobs and on the macOS wheel job, and the macOS wheel built locally was tagged `macosx_26_0_arm64`, installable on the build host's macOS only.
What it took to make wheels that install anywhere their tags claim:

52. **CPython references are weak on Linux too.**
    GHC's loader binds calls through the PLT lazily, but the shim stores the addresses of `PyType_GenericAlloc` and `PyObject_Free` in slot tables, whose relocations are resolved when GHC loads the library for Template Haskell; the Ubuntu jobs stopped there with `undefined symbol: PyObject_Free`.
    `weakapi.h` no longer limits its pragmas to macOS, `scripts/gen-weakapi.sh` reads GNU `nm` output and rejects strong references on Linux as well, and so does the `h2py-weakcheck` suite; at run time the references bind to the interpreter as before.
53. **Each thread's stack bounds are found once.**
    The headroom check of 33 asked `pthread_getattr_np` on every call, and glibc answers it for the initial thread by reading `/proc/self/maps` and querying the stack rlimit: a call from Python's main thread cost 185 to 300 µs on Linux, against 1.6 µs from another thread.
    The lowest address of the thread's stack is now kept in a thread-local after the first call.
54. **Everything built on macOS targets macOS 11.**
    `cabal.project` passes `-mmacosx-version-min=11.0` to GHC's C compiler, assembler and linker as `package *` `ghc-options` under `if os(osx)`, which enter every store package's hash; `MACOSX_DEPLOYMENT_TARGET` does not, so an existing store kept the host's version.
    11.0 is the minimum of GHC's own release libraries and the first macOS for Apple silicon.
    GHC does not recompile a module when only these options change, so `scripts/build-wheel.sh` refuses any object of the local packages built for a newer macOS, and sets `MACOSX_DEPLOYMENT_TARGET` to the same version for delocate, which then checks every library it bundles.
55. **A wheel's platform tag is the build's, not the interpreter's.**
    The CI wheel job's python.org interpreter reports `macosx-10.13-universal2`, and delocate refused an arm64-only module under that tag; `hatch_build.py` now tags a macOS wheel from the target in `cabal.project` and the architecture `lipo` reports for the built library, and a Linux wheel `linux_<arch>` for auditwheel to replace.
56. **Linux wheels are `manylinux_2_28`.**
    `scripts/manylinux-wheel.sh` runs inside the PyPA `manylinux_2_28` image with GHC 9.12.4's rocky8 (x86_64) or deb10 (aarch64) bindist, both built on glibc 2.28, and cabal-install 3.14.2.0, each pinned by SHA-256; it builds a copy of the tree, so that a checkout shared with the host keeps its own `dist-newstyle` and `cabal.project.local`.
    auditwheel bundles the Haskell libraries, `libgmp.so.10` and GHC's `libffi.so.8`; the static route stays closed on x86_64 Linux, whose bindist archives are not position independent.
    No musllinux wheel is built and only wheels are distributed, by the maintainer's decision.
57. **Every wheel carries its licences.**
    hatchling resolves `project.license-files` before any build hook runs, so the files are committed under `h2py-examples/python/`: `LICENSE`, and `third-party-licenses/` with one section per Haskell library the build plan links in, GMP's notice with the LGPL-3.0 and GPL-3.0 texts, and libffi's licence.
    `scripts/wheel-licenses.py --check`, run by the hook, `scripts/test-all.sh` and CI, fails when a linked library has no section or the licence expression in `pyproject.toml` misses an identifier.
    A GHC installation puts GHC's own licence in the documentation directory of every boot library, `text` and `bytestring` included, so the boot libraries' texts come from GHC's source tree (`--write --ghc-source`).
58. **The release gate installs every wheel as a user would.**
    CI builds the wheels on `macos-26`, `macos-15-intel` and in the manylinux image on `ubuntu-24.04` and `ubuntu-24.04-arm`, installs each into a clean interpreter, CPython 3.12 and 3.14, away from any build tree, and runs the whole suite against it, the Linux wheels also in AlmaLinux 8, the oldest glibc their tag admits.
    `scripts/check-installed-wheel.py` requires the module and every Haskell library the process loads to come from the installed wheel, and the licence files and stubs to be installed.
    The build-and-test job runs on the same four platforms, the two a developer machine here can test (Apple silicon, and aarch64 Linux in Docker) included, so that CI never rests on a local run.

Three reviewers with one lens each (runtime, FFI and concurrency; soundness of the result, licensing included; CI and ergonomics) were told to refute the plan of 52 to 58 while it was being implemented, and the verification runs turned up three more faults.
Every finding was fixed or answered:

59. **Stack bounds, second round.**
    A failed lookup is no longer remembered (glibc's needs a file descriptor for the initial thread, so running out of them at the first call had turned the guard off for good), and a call that finds too little room looks again before refusing, so a stack rlimit raised after the first call is honoured; one lowered after it is not seen, which the code says.
    `test_recursion.py` runs the recursion on two threads in turn as well, the second after the first has exited.
60. **A missing interpreter function is an `ImportError`.**
    `scripts/gen-weakapi.sh` also writes a table of every weak reference with its address, and `PyInit_` (and `PyModExport_`) of `<h2py/init.h>` checks it before the module definition reaches CPython: an interpreter that lacks one of them gets an `ImportError` naming the missing functions instead of a call to address 0.
    Measured through `PYTHONPATH`, despite the `cp312-abi3` tag: CPython 3.10 names `PyErr_GetRaisedException`, `PyErr_SetRaisedException`, `PyObject_GetTypeData` and `PyObject_Vectorcall`, and 3.11 the first three.
    The check first sat in the exec slot, which CPython before 3.12 never reaches, since it refuses the module's `Py_mod_multiple_interpreters` slot first (`SystemError: ... unknown slot ID 3`); the implementation review caught that.
61. **Licences, completed.**
    The GHC source and the store packages' sources were searched for third-party copyright notices: xxHash is compiled into the runtime (`rts/Hash.c`) and into `hashable`, and LLVM's ELF relocation tables into the runtime's linker on Linux, so `XXHASH-LICENSE.txt` and `LLVM-LICENSE.txt` join the notices, `NCSA` joins the licence expression, and `EXTRA_NOTICES` in `scripts/wheel-licenses.py` records which package needs which.
    bytestring's and text's per-file notices are covered by their packages' licences, ghc-bignum's wrappers by ghc-bignum's, and GHC ships no Unicode data licence for its generated tables, so none is added.
    `--check-wheel` checks the repaired wheel itself, since the build plan is a superset of what delocate bundles and cannot see what auditwheel adds: every bundled Haskell library must belong to the plan's closure, anything else must be GMP or libffi, and the wheel's metadata must carry every licence file.
    `GMP-NOTICE.txt` names the exact sources (gmp 6.1.2-11.el8's source RPM for Linux, gmp 6.3.0 and ghc-bignum inside `ghc-9.12.4-src.tar.xz` for macOS), and `scripts/manylinux-wheel.sh` refuses an image whose gmp package the notice does not name; libffi's licence is the one in the 3.5.2 tarball GHC builds.
    Whether the source directions satisfy the LGPL is the maintainer's judgement; the notice gives what a recipient needs to rebuild either library.
62. **Builds are reproducible.**
    `cabal.project` pins the Hackage `index-state` at the state the notices were generated from, CI uses cabal-install 3.14.2.0 like the manylinux bindists, the manylinux image is pinned by tag, and the build and repair tools with all their dependencies are locked with hashes in `h2py-examples/python/build-requirements.txt`; the wheel's metadata version is pinned at 2.4.
    Before the pin, any release of a dependency on Hackage would have failed every wheel build on the licence check.
    The image is pinned by tag rather than digest; besides libgmp, which is checked by version, it shapes the wheel through its patchelf and CPython headers, which the tag pins as well.
63. **CI's cache keys were empty.**
    `ci/scripts/calc-cache-keys.js` passed each further pattern to `hashFiles` as its workspace argument, so the hashes of `cabal.project` and of the sources came out empty and a change to them kept the old key; it now passes one newline-joined pattern.
    Wheel jobs have cache keys of their own, and every job saves its store only when it is complete and was not restored exactly.
64. **The macOS floor and the glibc ceiling.**
    `-optcxx-mmacosx-version-min=11.0` covers C++ sources; a target with a minor version (11.3) is refused, since a wheel tag from macOS 11 on names the major version only.
    Haskell foreign imports carry no availability information, so no gate can prove that a wheel runs on macOS 11 short of running it there, which no hosted runner offers; the review's scan of the wheel's system imports found nothing newer than macOS 10.15, and the objects are built for 11.0.
    glibc 2.41 and later refuse libraries that ask for an executable stack, so `scripts/build-wheel.sh` fails when a bundled one does.
65. **The gate, completed.**
    Every job has a timeout, a newer push to a pull request cancels the older run, macOS and Linux wheels are tested by separate jobs so that one platform's failure does not hide the other's results, each test also runs under a uv-managed CPython (python-build-standalone), the glibc floor runs in a clean AlmaLinux 8 with its own CPython 3.12, and the `Wheels` job collects the tested wheels with their checksums into one artifact, the check to require in branch protection.
    Publishing (a GitHub release, PyPI) is left to the maintainer.
66. **Found while verifying.**
    CPython 3.14 passes a local to a call without a new reference, so `sys.getrefcount` reports one less than 3.12 and 3.13 for an object only a local holds; the refcount tests compare with a fresh object measured the same way, in the same frame, and pass on 3.12, 3.13 and 3.14.
    `scripts/build-wheel.sh` runs its Python steps isolated, since the `build/` directory at the root passed for the `build` package when it was not installed.
    `scripts/install-module.sh` replaces the module with a new file, since macOS kills a process that maps a signed binary rewritten in place after it had been loaded.
67. **Deferred, with reasons.**
    Two H2Py modules in one process: design 5.9 said auditwheel's renaming kept two wheels apart even under `RTLD_GLOBAL`, which is wrong, since renaming changes sonames and not symbols, and on macOS the flat namespace makes a second module abort; the design is corrected, and a guard that turns the second import into an `ImportError` is separate work.
    Making the wheel scripts reusable by downstream projects (package directory, module name and smoke test as parameters) is separate work too.

The implementation review, again three reviewers with one lens each, found the following, all fixed but one:

68. **The symbol check moved to `PyInit_`** (see 60), where CPython before 3.12 reaches it.
    A recheck of the stack bounds whose lookup fails keeps the bound already found and refuses the call, instead of letting it through unguarded.
    The recursion tests assert the shim's own message, a depth over ten on every thread, and a second thread on a 64 MiB stack that must go deeper than the first, so a bound shared across threads fails them.
    `gen-weakapi.sh --check` and `h2py-weakcheck` fail when the library shows no CPython reference at all, rather than passing on a wrong file.
    Answered rather than changed: a stack rlimit lowered after a thread's first call is not seen (CPython 3.14 caches its own stack bounds per thread the same way, and seeing it would take a system call per call); a single level that uses more than the 256 KiB margin defeats the guard, as it did before.
69. **The wheel's own licence names its holder**: `h2py-examples/LICENSE` read `Copyright 2026` with no name, and now matches `h2py/LICENSE`.
70. **The repaired-wheel check checks what it claims.**
    It finds shared libraries by their magic bytes anywhere in the wheel, requires the GHC runtime among them, allows nothing but `libHS*` on macOS and auditwheel's `libgmp` and `libffi` on Linux, and compares GMP (the SBOM on Linux, the version string in `libHSghc-bignum` on macOS) and libffi with the versions the notices name.
    Every licence file must be in the wheel byte for byte, listed as a `License-File`, with the `License-Expression` of `pyproject.toml`, which must be a plain conjunction and now names `HaskellReport` (base, array and ghc-internal carry the Haskell Report's licence); `GMP-NOTICE.txt` must name the plan's GHC.
    The executable-stack check requires exactly one `GNU_STACK` header without the E flag in every library and fails when `readelf` does, and CI runs the Linux wheels in Debian 13 (glibc 2.41) as well as AlmaLinux 8.
    One build leg checks the boot libraries' licence texts against GHC's checksummed source release.
    The wheel is repaired and checked in a staging directory and reaches the wheelhouse only when every check has passed, replacing only this package's earlier wheels.
    `--write` lists the packages it adds, for their C sources to be read for code of other origin; a table of reviewed versions was judged more machinery than the risk warrants.
71. **CI, the second round.**
    The fourmolu job had failed on the first run on two counts: it could not parse two files without `BangPatterns`, which GHC2021 turns on for the foreign library, and `latest` resolved to a fourmolu that orders imports differently from the editor hooks' 0.20.0.0; it now pins 0.20.0.0 and passes `-XBangPatterns`, and every tracked file passes.
    A `CI` job fails unless every other job succeeded and is the one to require in branch protection, since GitHub counts a skipped job as passed; the wheel jobs save the cabal store right after building the dependencies; the checks after a build no longer hide one another; the Ubuntu label is pinned; `gmp-devel` is installed at the image's gmp version, so that the live mirrors cannot upgrade gmp away from the notice; the build job installs `libgmp-dev` itself, which the setup action does not; the token is read-only.
    Not changed: one architecture's wheel failure still skips the other architecture's tests of the same platform, since splitting the jobs per architecture would duplicate them.
    The GMP source offer points to gmplib.org, AlmaLinux's vault and downloads.haskell.org, all reachable today; attaching the sources to each release would remove that dependence, and is the maintainer's call.
72. **The concurrency tests wait for what they check.**
    The second CI attempt failed one test on the Intel runner under CPython 3.14: the test sized a detached call from a 200-repetition measurement of one to three milliseconds, which a single stall of the thread inflates several times over, and then probed once, 0.1 s after starting the call, which by then had ended.
    Every probe that used to follow a fixed sleep now polls until it sees the other thread's call holding the object, with a probe that changes nothing when it gets through (`scale(1)`, `incr(0)`, a reader); the call is sized from a measurement of at least a tenth of its target; two parallel detached readers are shown to overlap by the second ending while the first still holds, not by a bound on their total time; the `interrupt_main` test waits for its timer rather than cancelling it after 50 ms, and checks that the timer was due during the loop; the detached window of `sleep_then_check` is a second instead of 0.4 s, the SIGINT bound 3 s instead of 1.5 s (the uninterrupted loop takes about 18 s), and the call-overhead bound applies to the best of five batches.

## Wheels of other projects (2026-09-23)

The reuse deferred in 67 is done: a project that uses H2Py builds its wheels with the same hook and scripts, and the tutorial's "Shipping wheels" section walks through it.

73. **What a wheel holds comes from its `pyproject.toml`.**
    The hook and `build-wheel.sh`, `manylinux-wheel.sh` and `test-wheel.sh` read the module, its foreign library and its Cabal package, a smoke test, and the test suite with its requirements from a `[tool.h2py]` table, which `scripts/wheel-config.py` resolves, defaults from `project.name` included, so that all of them agree; the example spells its values out, and the first three are also the defaults.
    `H2PY_PACKAGE_DIR` names the packaging directory (default `h2py-examples/python`), `configure-python.sh` writes the include directory for `h2py` and the packages in `H2PY_CABAL_PACKAGES` (default `h2py-examples`), to which the hook adds the wheel's own, and the hook finds the project as the nearest `cabal.project` above it rather than two directories up; `H2PY_MODULE` is gone.
    The hook builds `<package>:flib:<name>` rather than the whole package, `build-wheel.sh` replaces the previous wheels of the distribution it built, whatever its name, and `wheel-licenses.py --check-wheel` takes the module's name (`--module`), which it had derived from the foreign library's.
    `test-wheel.sh` installs the wheel with the dependencies its metadata declares, runs the installed-wheel check and the smoke test there, and only then adds the suite's requirements; it had installed the wheel with `--no-deps` next to numpy and pytest, which a wheel with dependencies of its own fails.
74. **A module without submodules ships a stub package.**
    `h2py-stubs.py` writes `<module>.pyi` and `py.typed` beside such a module, which in a wheel put a `py.typed` at the top of `site-packages`, shared by every distribution that does the same, and a `.pyi` that mypy does not read beside an installed extension (measured: it reports the import as missing, and resolves `<module>-stubs/`); `check-installed-wheel.py` already required `<module>-stubs/`, so such a wheel failed its own check.
    The hook passes the new `--stub-package`, which writes `<module>-stubs/` with submodules or without; the example has submodules, and its wheel is unchanged.
75. **Replayed on a project of its own.**
    The tutorial's section was followed, its code blocks taken verbatim, on a scratch project, `h2py-counter` with the module `counter`, that takes H2Py through a `source-repository-package`: only `h2py` had to be built, the rest of the cabal store being shared with this repository's build; `wheel-licenses.py --write` gave the example's notices back unchanged, since H2Py's closure is the example's whole closure; the macOS wheel, built with CPython 3.12 as the section says (and with 3.13 in an earlier run), passed every check of `build-wheel.sh`, and `test-wheel.sh` under 3.12 and uv's 3.14, and mypy resolved the installed stubs.
    Its `manylinux_2_28` aarch64 wheel, built by `manylinux-wheel.sh` in the pinned image with `H2PY_PACKAGE_DIR=python`, bundled its libraries into `h2py_counter.libs/` and passed `test-wheel.sh` in `python:3.14-slim` and `almalinux:8`; the example's wheels, built with every default, pass as they did.
