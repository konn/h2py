# Implementation notes

Decisions taken while implementing `docs/H2Py-DESIGN.md` (v1.6) that the design leaves open, or that deviate from its text.
Each entry names the section it touches and why.
The design document itself is kept as written; these notes are the amendments.

## Build and distribution (5.10, R1)

1. **Weak CPython references on macOS.**
   GHC loads `libHSh2py` into its own process, with no interpreter, to run the Template Haskell splices of any module that uses `pyclass`, `pymethods` or `pymodule`, and dyld on current macOS binds every symbol of a library at load time; so any CPython reference in the library, function or data, makes that load fail.
   Cabal passes neither `ld-options` nor `ghc-shared-options` to a library's dylib link, which rules out a linker flag.
   The library therefore references the interpreter only through weak imports: every Haskell `foreign import` goes through a one-line wrapper in `h2py/cbits/api.c`, every C translation unit of the shim includes the generated `include/h2py/weakapi.h` (`#pragma weak` per symbol, regenerated by `scripts/gen-weakapi.sh` from the undefined symbols of the built dylib and verified by `--check`), and no CPython data symbol is referenced anywhere: `PyExc_*`, `Py_None`, `Py_True`, `Py_NotImplemented` and the built-in type objects are fetched through `builtins` at first use and cached in `h2py.c`.
   Linux needs the data-symbol half of this, since a lazy `dlopen` tolerates an undefined function but not undefined data; the same source builds there unchanged.
   The design owner accepted the scheme as the design (it also keeps the library loadable in `cabal repl` and HLS without an interpreter), with two conditions that are met: the no-data-symbol rule is a stated invariant, and the check is wired into the build as the `h2py-weakcheck` test suite (a source lint plus, on macOS, an `nm -m` pass over the built dylib).
   The recorded fallback, should the weak scheme prove fragile, is a splice package that does not depend on `h2py` and emits names with `mkNameG`.
2. **`-undefined dynamic_lookup`** is what GHC already passes when it links a dylib on macOS; the `ld-options` in the cabal files matter only for the foreign library's final link.
3. **RTS options.**
   The example module passes `-N` through `H2PY_RTS_OPTS` in its C file, as 5.9 recommends for the demo; the library itself adds only `--install-signal-handlers=no`, and the `H2PY_RTS_OPTS` environment variable is appended at initialisation.
   `keep_cafs` is on, because the RTS lives in a library whose code is entered through adjustors long after initialisation.
4. **Extension file name.**
   Cabal names the artifact `libh2py_examples.dylib`; `scripts/install-module.sh` copies it to `build/h2py_examples.abi3.so`, which CPython imports.
5. **linear-base 0.7.**
   `cabal.project` constrains linear-base to the 0.7 series, matching pure-borrow's freeze and CI matrix, on the design owner's decision; nothing needed 0.8.

## The `Py` world and the delimiters (5.1)

6. **Fresh scopes.**
   Lifetimes are erased, so a rank-2 body is instantiated at `'Al 0` behind `withFreshScope`; the rank-2 binder is what keeps the body from assuming anything about the scope, exactly as `newLifetime'` does upstream.
7. **Finalisation on the restore path.**
   When `detach`'s restore finds the interpreter finalising, `DetachRestoreRefused` is thrown; the trampoline's exceptional path then finds the thread unattached, releases the arena's Haskell state without touching CPython (the +1s leak), and parks the thread for good, which is CPython's documented behaviour for a daemon thread at exit.
8. **`parPy` and branch exceptions.**
   `parBO` at the pinned commit does not propagate a branch's exception (the structured version of 4.4 is a later upstream change), so a Haskell exception inside a `parPy` branch can hang the call; the shipped kernels validate their inputs first and answer `Left`.

## References, errors, conversions (5.2, 5.5, 5.6)

9. **Constants of the interpreter** (`None`, `True`, `False`, `NotImplemented`) are registered in the arena like any other reference when handed out as `Bound`, with an incref, so that the sweep's uniform decref stays correct.
10. **Lazy errors** hold the exception class as a raw pointer: static for the built-ins (read through a pure foreign import of `h2py_exception_type`, which touches no interpreter state), and for classes made by `newException` an `IORef` cell filled at module init and read through a `NOINLINE` `unsafePerformIO`, so that `pyErr` stays pure as 5.5 asks.
    The cell is write-once: a second fill and a read before the fill are an `error` naming the class, never a `NULL` that reaches CPython; nothing can force a `pyErr` value before init, since Haskell code runs only inside calls.
11. **`fromPy` for containers** iterates in an IO loop inside the trusted library and releases each item's reference as soon as it is converted, instead of wrapping each iteration in `attach'_`: those references never become a `Bound` visible to user code, so they need no arena slot and no constraint; `attach'`/`attach'_` are the loop tools for user code, which cannot release early.
   Confirmed by the design owner and recorded in 5.6.
12. **`ToPy` for `Set` and `Map`** is not provided, because linear-base has no `Consumable` instance for them and `ToPy` requires one; `FromPy` for both exists.
13. **`Integer` beyond 64 bits** goes through `PyNumber_ToBase(…, 16)` and a decimal string in the other direction; the limited API has no direct big-integer accessor at the 3.12 floor.
14. **`PyObject_Length`** is a macro alias of `PyObject_Size` in the headers; the weak list carries the real symbol.

## Registration (5.4, 5.11, 5.12)

15. **The `detached` registration** is a marker newtype `Detached f` wrapped around the whole function value, selected by `& detached`, with `PyCallable` and `PyMethod` instances that push it through the arrows to the body; a `BO π` or `BIO π` body then runs under `detach`, and marking a `Py π π` body is a type error, since a `Py` body cannot be detached (the design owner's condition).
16. **Option combinators are multiplicity-polymorphic** in the registration (`param 0 "x" :: s %m -> s`) and `H2Py` re-exports no `&`, so that `fn "add" 'add & param 0 "x"` chains under `Data.Function`'s and `Prelude.Linear`'s `&` alike; a registration table is plain data.
17. **`pymethods` is required** for every class listed in a `pymodule`, with an empty list for a class without methods, because `pyclass` cannot know whether a `pymethods` follows.
18. **Class names are module-qualified** in the type spec (`h2py_examples.Counter`), which is what gives the class its `__module__`.
19. **Module docstrings** come from the Haskell description (`msDoc`), set as `__doc__` at init; the C `PyModuleDef` carries none.
20. **The `foreign export`** that `pymodule` generates is typed `Ptr PyObject -> IO Int32`, because a `CInt` result would need the constructor in scope in the user's module.
21. **Class type cells** are top-level `NOINLINE` `IORef`s generated per class; a class used before its module is initialised answers `RuntimeError`.

## Buffers (5.7)

22. **View scopes.**
    `requestBufferMut` is typed `Bound π PyAny %1 -> Py π γ (PyResult (BufferMut π e))`, the request scope being the view scope, and `requestBufferShare` answers a view at the requesting scope, because the shim records a view in the innermost arena and a view at an outer scope could outlive the arena that releases it; `withBufferMut`, `withBufferShare`, `releaseBuffer` and `newArray` keep the design's signatures (see `Note [Buffer views are scoped by the requesting arena]`).
23. **NumPy's own errors** for a read-only or non-contiguous array (a `ValueError` from `PyObject_GetBuffer`) are rewritten into `BufferError`, which is what the design promises.
24. **`Bool` buffers.**
    `Storable Bool` is four bytes wide, so NumPy's one-byte `bool_` arrays match the `CBool` instance, not `Bool`.
25. **The registry flag** is recorded on the view at request time: a shared view of a writable exporter has `readonly == 0`, so the flag cannot be recovered from the `Py_buffer` (a bug the tests found).

## Concurrency (5.1, 5.8)

26. **`parPy` guards its branches**: each runs under `try` after its own attachment has been released, and the parent rethrows the first exception once both have completed, so a Haskell exception in a branch reaches the trampoline as a Python exception instead of hanging; an asynchronous exception delivered to the waiting parent still leaves the branches running to completion, which only the structured upstream `parBO` removes.
27. **`KeyboardInterrupt` and attached loops.**
    A Python timer thread cannot deliver `interrupt_main` while a call holds the interpreter, so `checkSignals` inside an attached loop only ever sees a real signal (the tests send `SIGINT` from a subprocess); the design's shape, detach for the long stretch and check after, is `sleep_then_check` in the examples.

## Packaging (5.10, 5.11)

28. **Wheels** are built by a hatchling hook that runs `cabal build` from the repository checkout, and repaired with `delocate` on macOS: 36 Haskell runtime dylibs are bundled, 12.8 MB compressed and 62 MB unpacked; the platform tag follows the minimum OS version the libraries were built for, so a portable wheel needs `MACOSX_DEPLOYMENT_TARGET` set when the store and the tree are built.
    `libgmp` is statically linked into GHC's `ghc-bignum` on macOS, so no LGPL dylib is bundled there.
29. **Stubs** are written by `scripts/h2py-stubs.py` from `__h2py_stub__`, and `mypy --strict` passes on the example's root stub; a class registered with an ABC renders the ABC as a base without type arguments, which `mypy --strict` rejects for `Sequence`.

## Measured (Phase 1 gate, R3, and Phase 4)

On this machine (Apple silicon, CPython 3.13.0, GHC 9.12.4, `-O2`, `-N`), per call, median of 50k calls:

| call | ns |
|------|----|
| `add(1, 2)` | 740 |
| `c.incr(1)` | 610 |
| `c.get()` | 540 |
| `c.label()` | 690 |
| pure Python `add` | 33 |

The path measured is the real one: adjustor entry on a bound thread, `mask`, pool drain, arena push, argument binding and conversion, the dereference and its compare-and-swap, result incref, sweep and pop.

`nparallel.sort_in_place` (`qsortDC` over a `float64` buffer, detached, `-N` on 10 logical cores) against `numpy.sort`, best of 5:

| n | `numpy.sort` | `sort_in_place` |
|---|---|---|
| 1e5 | 2.1 ms | 2.2 ms |
| 1e6 | 26.4 ms | 22.7 ms |
| 1e7 | 327 ms | 227 ms |

`nparallel.sum` reads each half of the shared view with an indexed loop, since the unrestricted vector API has no fold, and is about 2.2 times slower than `numpy.sum` at 1e7; `nparallel.fft` (pure-borrow's `fftDC`, two conjugation passes around it to match NumPy's sign convention) is far slower than pocketfft and carries the twiddle recurrence's drift, which the README's Numbers section quantifies with a core-count sweep from `scripts/bench-nparallel.py`.

## The adversarial review round (2026-09-23)

Four reviewers with one lens each (linear ownership, type-level soundness, runtime/FFI/concurrency, ergonomics and the phase gates) were told to refute the integrated implementation; every substantial finding was then handed to two independent refuters, and none was refuted.
What each confirmed finding changed:

30. **Shared buffer views cannot be released early from safe code.**
    `BufferShare` is unrestricted, so `releaseBufferShare` on it typechecked twice; the shim's release is now idempotent, the view struct lives until the sweep of the arena that recorded it, and the function is no longer exported from `H2Py.Buffer`.
31. **Trusted instances are sealed** (`Note [Sealed classes]` in `H2Py.Object.Internal`): `PyClass`, `PyFrozenClass`, `PyTypeOf`, `PyExtends` and `PyExceptionClass` carry a witness method whose constructor only the `.Unsafe` and `.Internal` modules export; the splices produce it, every trusting operation forces it, and a hand-written instance in safe code cannot retag a reference, alias another class's cell or lie about a type object.
32. **No `NULL` type object reaches CPython**: a generated `pyTypeOf` throws `ClassNotRegistered` (a `RuntimeError` in Python) before its module is initialised.
33. **C stack headroom** is checked at every trampoline entry (`h2py_call_begin`) and a call with less than 256 KB left raises `RecursionError`, because a Python recursion through H2Py costs far more C stack per level than CPython's own accounting assumes.
34. **The constant caches are warmed at module exec**, so a lazy `PyErr` forced on a detached thread never imports anything.
35. **The forked-child guard is on the trampoline**, not only on `attach`: every call in the child of `os.fork()` raises `RuntimeError` naming the `spawn` start method.
36. **Subtype allocation is paired with its class**: the type a `tp_new` records is taken only by the first allocation of that class in the constructor, searched outwards through nested scopes, so a helper object built inside a constructor gets its own type.
37. **Linear values are consumed on every `Left` path** of `newObject`, `newObjectWith` and the list, vector and tuple `ToPy` instances.
38. **`parPy` and `parBIO` guard their branches** (see 26); a user kernel is written `detach (parBIO …)` for now.
    `parBIO` is interim by decision of the design owner: it goes when the structured upstream `parBO` of Phase 0.5 lands, so that the API never carries two parallel combinators for good.
39. **`PyHandle` is `Dupable` and `Movable`**, as an unrestricted handle should be; `call0`, `callMethod0` and `emptyTuple` give the zero-argument shapes a type.
40. **Deallocators report a Haskell exception** through the unraisable hook with the converted error raised, saving and restoring the caller's pending exception.
41. **`copyPayload`'s transient claim** is taken and released under `mask`.
42. **Arenas that lost the interpreter** are abandoned without touching CPython on the `attach` and `attach'` exit paths too.
43. **Stubs import every module a dotted hint refers to**, and the built-in container tags render with type arguments.
44. **Cycle collection** stays a documented non-goal of 0.1 (design section 1): a `PyHandle` stored in a payload is invisible to CPython's cycle collector, so a cycle through a Haskell payload leaks.
45. **Gate coverage** (every operation's refcount deltas, callback re-entrancy, asynchronous poisoning, `attach'` hold release, receiver-form `BIO` bodies, the fork and recursion guards, `fft` and a stencil in `nparallel`, the `qsortDC` inspection, the counter's golden stub) was added in a second round of work packages after the fixes above.
46. **Slot bodies in both forms.**
    `Compare`, `GetItem`, `SetItem`, `DelItem`, `Next`, `Exit` and the in-place number operations accept a body returning `r` or `PyResult r` through a small `SlotResult` class, as methods do through `ToResult`; `Iter`, `NextObject`, `Enter` and the binary and unary number operations keep the `PyResult` form, because their result is a reference at the call's scope, which an existential chosen outside the scope-polymorphic body cannot name.
47. **Registrations are looked up module-qualified first** by `pymodule`, so two classes with one base name in different modules (the tutorial's `Counter` next to the example's) resolve to their own registration.
48. **`PyHandle` is `Copyable`** as well, so a payload holding a `Ref (Maybe (PyHandle t))` reads it back with `copyRef`; the tutorial has the section.
49. **Stubs under `mypy --strict`.**
    The example's stub package (root plus one file per submodule) is committed under `h2py-examples/stubs/`, regenerated by `scripts/h2py-stubs.py --output`, checked by `--check` in `scripts/test-all.sh` and CI, and passes `mypy --strict`; generic ABC bases render with `Any` type arguments, `__contains__` takes `object`, a class registered but deliberately absent from every module is hinted `Any` by its example.
    The example's `Stack` registers `collections.abc.Sized` rather than `Sequence`, since a stack without slice support is not a typed sequence.
50. **The `qsortDC` inspection** at `Storable Double` finds the workload specialised but the scheduler's `Traversable` and `RandomGen` dictionaries retained, because pure-borrow's `divideAndConquer'` has no `INLINABLE` pragma; the wanted property is recorded with `expectFailBecause` in the `h2py-inspection` suite, and the fix is upstream.
51. **Gate tests added**: every operation's refcount deltas on success, `Left` and exception paths; callback re-entrancy answering `busy`; two handles to one object; asynchronous poisoning through `timeout` and `throwTo`; a hold released at the end of `attach'`; receiver-form `BIO` and detached `BO` bodies releasing the interpreter; a `parBIO` branch error surfacing as `RuntimeError`; the fork and recursion guards in subprocesses; an unregistered class answering `RuntimeError`; a hand-written unsealed instance failing at first use; a subclass constructor building helpers of their own type.
